# 28 · 新手使用教程（小白版）

> 这份文档面向第一次打开成员管理插件的人。全程不需要看懂代码，照着念、照着点就行。
> 想查设计细节看 `docs/11-公司化改造-接口契约.md`；想查版本变更看 `CHANGELOG.md`。

---

## 一、这插件到底给了你什么

一句话：**它把你的一台 DSH 变成一家小公司**——有部门、有员工、有工号、有工单、有验收。

平时你跟 AI 对话，是「一个人问、一个人答」。装了它之后：

- 你可以**建部门**（工程部、文档组、内容部……）
- 你可以**招员工**，每个员工有自己的岗位、职责、模型、能用的工具
- 你可以**下单**，让公司自己把活派给合适的人
- 员工干完**回报**，你（或经理）**验收**，通过才算完成

它跟 DSH 原生「子代理」的区别：子代理是临时拉一个就完事，这里是**长期组织**——员工有档案、有历史、有工号，派工有记录、有成本、可追溯。

它其实分两层，理解这一点后面就不迷糊了：

| 层 | 作用 | 存在哪 |
| --- | --- | --- |
| **名册层**（`member_*` 工具） | 给 DSH 已有的成员挂"中文名 / 岗位 / 职责 / 技能 / 指定模型" | `registry.json` |
| **公司层**（`company_*` 工具） | 部门、工号、等级、工单、派工、验收、成本 | `company/` 目录 |

名册层是**覆盖层**——它不改 DSH 本身，只是在外面贴了张标签。公司层是**真运行时**——它真的会创建会话、唤醒员工、收回结果。

## 二、装完之后第一件事：重启

插件改动**必须重启 DSH 才生效**，不支持热重载。

> 为什么：插件是以代码形式加载进 DSH 进程的，进程不重启，跑的还是老代码。这一点后面每次改插件代码都成立。

重启完，打开**设置 →「成员管理」**，看到四个页签就说明装好了：

```
总架构 ｜ 员工中心 ｜ 工作流 ｜ 备份与更新
```

右侧栏还有一个**「工作网」**按钮——那是你以后最常盯的地方。

## 三、五分钟跑通第一单

下面五步，照着做，5 分钟能从零到看见一个员工真的把活干完。

### 第 1 步：建一个部门

进「总架构」页签 → 点**新建部门**。

最省事的办法是用「一句话建组」：直接写人话。

```
新建「文档组」：文档编写负责正文，文档审阅负责校对。
```

点**解析预览** → 看一眼它要建几个成员 → 点**确认创建**。

> 你会看到：部门出现在架构图上，成员带上了工号（`E0001`、`E0002`……），部门带编号（`D01`）。

**为什么先建部门**：工单要靠部门来派。没部门，单子只能躺在「排队」里——面板会直接提示你「还没有部门，先建部门再派工」。

### 第 2 步：让员工可用

建完之后在**员工中心**页签确认一下：员工状态应该是「启用中」，模型那一栏不是空的。

如果模型是空的，给这个员工指定一个——点员工卡片改，或者跟我说：

```
把这个部门的员工模型都设成 deepseek 那个快的
```

### 第 3 步：下单

两种方式，任选。

**方式 A：跟我说话**（推荐，最像人）

```
帮我下一单：给文档组写一份《插件安装说明》，800 字左右，
要求：含安装三步、常见报错三条，做完把文件路径告诉我。
```

我会调用 `company_order` 建单。你会看到返回一个 `orderId`，比如 `mvw08d7z-n12piv`。

**方式 B：点面板**

打开「工作网」→ 点**下达工单** → 填「任务标题」（一句话说清要做什么）→ 提交。

> 单子会出现在**排队**泳道。

### 第 4 步：看着它自己跑起来

不用你做任何事。**调度器每 5 秒扫一轮**，会自动把单子：

```
排队 → 已路由（找到部门） → 执行中（派给具体员工，员工的 AI 真开始干活）
```

想看当前状态，随时问我：

```
看一下 mvw08d7z-n12piv 这单到哪了
```

或者点开「工作网」直接看泳道。

**派给谁了？** 系统按五级顺序找：你指定的人 → 路由规则 → 部门职责匹配 → 员工技能 → 兜底（找还有产能的最大部门）。找不到就停在「已路由」并记一条失败原因。

### 第 5 步：验收

员工干完会**回报**，单子进「已完成」泳道等你点头。

- 满意 → 点**复核通过**（或让我调 `company_review`，`pass: true`）
- 不满意 → 点**打回重做**（`pass: false`），单子退回，可以重新派

> 验收通过后单子才真正结单。如果员工报的是「失败」，单子会进**异常**泳道——见第八节怎么处理。

## 四、界面导览

### 四个页签

| 页签 | 干什么 |
| --- | --- |
| **总架构** | 建部门、改编号规则、改等级、套「游戏开发模式」等预设、看整张组织图 |
| **员工中心** | 看每个成员：中文名、岗位、职责、技能、模型、启用/停用 |
| **工作流** | 实时看板：谁在跑、跑什么、花了多少 token、用了多久（每 2 秒自刷） |
| **备份与更新** | 名册备份/恢复；插件版本检查、下载暂存、应用、回滚 |

### 工作网（右侧栏）

点「工作网」按钮才弹出，**不会自动弹**——这是故意的，免得干活时被打断。

上半部是**调度 · 任务流**，五条泳道：

```
排队 ｜ 已路由 ｜ 执行中 ｜ 已完成 ｜ 异常
```

旁边还显示：调度器在不在跑、部门产能条（在跑 / 空闲）、合计统计。

下半部是**组织拓扑**：管理层 → 部门 → 员工，每张卡显示工号、等级、当前任务、token 用量。空闲成员默认折叠。

泳道上的单点开能看：订单详情、派工历史（第几次派、派给谁、结果）、验收标准、依赖、上次派工失败的原因。

## 五、一张工单的一生

```
你下单
  ↓
[排队]        还没找到人
  ↓  路由
[已路由]      找到部门了，但还没派到具体人
  ↓  派工
[执行中]      员工的 AI 正在干
  ↓  回报
[已完成]  ←── 验收通过 ──┐
  ↓ 回报失败            │
[异常]  ── 重派/取消 ───┘
```

几条会影响到你的规则：

- **依赖**：下单时写「B 单要等 A 单完成」，B 就会卡住直到 A 完成。面板显示「依赖未完成」。
- **产能**：一个部门在跑的任务满了，新单会被拒绝并**等 10 秒再试**（不是永久失败）。
- **改派**：把单子改派给别人时，原来那个人手上的记录会被**吊销**，他再回报会被拒绝（提示已吊销），防止两份产物打架。
- **重复回报**：同一份派工回报两次，第二次会被拒。
- **取消**：没完成的单都能取消。**失败的单也能取消**（不会再卡在异常泳道里出不来）。

## 六、想做什么，怎么说

这些话直接对我说就行，我会翻译成对应的操作：

| 你想干的事 | 说这句 | 背后调用 |
| --- | --- | --- |
| 建个部门 | 「新建一个内容部，做文案和封面」 | `company_admin` createDepartment |
| 招个人 | 「招一个审稿的，挂到文档组」 | `company_hire` |
| 派活 | 「让文档组写个安装说明」 | `company_order` |
| 看进度 | 「那单到哪了」 | `company_status` |
| 催一下 | 「问问文档组卡在哪了」 | `company_ask` |
| 换人做 | 「改派给 E0003」 | `company_assign` |
| 验收 | 「这单可以，通过」 | `company_review` pass=true |
| 打回 | 「写得不行，重做」 | `company_review` pass=false |
| 不做了 | 「这单取消」 | `company_cancel` |
| 临时加人 | 「雇个临时工，最多干 3 单」 | `company_admin` / 面板「雇临时工」 |
| 看花销 | 「今天花了多少 token」 | `company_status` |

### 想让几个活同时干（并行）

单张单派出去，员工本来就是并行的。麻烦的是「一批活里有先有后」——一张一张下还要自己记谁等谁。这种情况直接丢一张任务图：

```js
company_plan({
  group: "改版",
  tasks: [
    { key: "调研", type: "research", title: "摸清现有三类页面的信息结构" },
    { key: "设计", type: "design",  title: "出方案",              deps: ["调研"] },
    { key: "文案", type: "writing", title: "写文案",              deps: ["调研"] },
    { key: "联调", type: "impl",    title: "按方案 + 文案落地",    deps: ["设计", "文案"] },
  ],
})
```

跑起来是这样：调研先干 → 调研一完成，**设计和文案同时**派出去 → 两个都完成，联调才解锁。

- 返回里的 `parallel` 是第一层同时起几个，`layers` 是整张图的层次。
- `deps` 写的是任务的 `key`，不是订单号。不写 key 会自动叫 `t1`、`t2`…
- 成环直接拒（`E_PLAN_CYCLE`），**一张单都不会建**，可以放心改完再提交。
- 同一层超过部门产能（默认 4 个）时，多出来的留在「排队」，下一轮接着派，这不算失败。
- 想查整批进度：`company_status({ group: "改版" })`，会给出 `done/running/pending/failed` 和每张单的状态。

## 七、工具速查

工具不用背，知道有这几类就行。**分线隔离**：不同角色只能调自己那条线的工具，越权会报 `E_TOOL_LINE`。

### 你一定用得到的（窗口线，5 个）

| 工具 | 干什么 |
| --- | --- |
| `company_order` | 下单。必填 `type` 和 `title`，其余可选 |
| `company_plan` | 一次下一张任务图，同层的并行干 |
| `company_status` | 查工单、员工、部门、成本；带 `group` 看整批 |
| `company_ask` | 对某单追问责任员工 |
| `company_cancel` | 取消工单 |

### 经理线（12 个，含上面 5 个）

`company_assign` 派工 · `company_review` 验收 · `company_borrow` 借调 · `company_escalate` 升级 · `company_report` 回报 · `company_hire` 招人 · `company_admin` 组织管理 · …

### 员工线（5 个）

员工自己能调的只有这几个：`company_accept` 接单 · `company_report` 回报 · `company_ask_help` 求助 · `company_status` · `company_ask`。

> **重要**：员工线只约束 `company_*` 开头的工具。宿主的常规工具（文件读写、命令执行、子代理）不在这张白名单里，员工照常能用。如果你的员工说「我没有权限读文件」，那是别的原因，先看第八节。

### 名册工具（16 个）

`member_list` 列成员 · `member_add` 加成员 · `member_rename` 改名 · `member_set_role` 设岗位 · `member_set_skills` 设技能 · `member_set_model` 指定模型 · `member_remove` 停用 · `group_manage` 管分组 · `member_sync` 同步核心成员 · `member_diagnose` 诊断 · `member_backup` 备份 · `member_group_from_text` 一句话建组 · `member_workflow` 工作流快照 · `member_update` 自更新 · `skill_list` · `model_list`

## 八、出问题了怎么办

### 单子一直卡在「排队」

没找到能干的部门。检查：是不是还没建部门？部门职责里有没有跟订单类型对得上的关键词？直接指定 `dept` 也能绕过筛选。

### 单子卡在「已路由」

找到部门了但派不到人。多半是**部门里的人都在忙**，等 10 秒会自动重试；或者这个部门的员工全是停用状态。点开订单看「上次派工失败」那一行，原因会写在那儿。

### 上游早就完成了，下游还在「排队」

先看下游那张单的「依赖」是不是已经全绿。如果上游确实「已完成」而下游一直不动，那是调度没转起来——正常情况下每 5 秒扫一轮，而且**上游一验收通过就会立刻推一轮**，不该久等。

0.4.x 有一个坑：调度器的轮询间隔被错设成 1 小时（把「attempt 僵死判定阈值」当成了轮询间隔），于是只有下单时那一批能靠事件立刻跑，依赖解锁之后的第二层要干等一小时，看起来就是「并行任务永远卡在排队」。0.5.0 修掉了，正常是秒级。

救急：工作网上点「立即调度」，或者直接调 `runScheduler`。

### 出现「异常」泳道怎么办

**「异常」泳道只显示当前卡住的失败单。** 已经结束的异常（已取消 / 已丢失 / 已结束但失败的单）会被挪到下方的 **「异常记录」** 区，并显示数量；点 **「清理记录」** 可以把这些历史异常从账本里一键删除（不可撤销）。

清掉当前异常有两条路：

1. **重派**：点「派工」，换个员工再来一次
2. **取消**：点「取消订单」。失败的单也支持取消

如果「异常」泳道是空的，会出现一个 **「重启进度」** 按钮，点一下会立刻触发一次调度，推进所有可派 / 可恢复的单。它和顶部的「立即调度」是同一个动作，只是放在异常泳道里提醒你「这里没有卡住的单，但你可以手动推一把」。

### 员工说「该工具不在当前岗位白名单中」（`E_TOOL_LINE`）

两个可能：

- 他调的是某个 `company_*` 工具，但他的等级不够（比如员工想调 `company_hire`）
- 这个岗位在配置里被加了工具黑名单（`toolPolicy`）

解决：要么换人，要么在部门/员工配置里放开。

> 常见误会：这条错误**不代表员工不能读写文件、不能执行命令**。那些是宿主工具，跟这层白名单无关。

### 员工说「求助但没人接」（`forwardedTo: null`）

他的部门没有配经理，求助没地方投。给这个部门指定一个经理，或者干脆由你直接接管这单。

### 报错 `E_NO_AGENTS`

宿主没给插件 `agents` / `subagents` 服务，派工发不出去。通常是宿主版本不匹配或插件没装全，重启 DSH 再看。

### 一直停在「执行中」不动

先看「工作流」页签，那个员工是不是还在消耗 token。如果确实半天没动静，直接改派或取消——**不要等**。订单进终态后，遗留的派工记录会在下次重启时自动标为已吊销，不会一直算在"在跑"里。

### 提示「操作失败」但事情其实成了

这是老版本的一个已知问题（`value is not lossless JSON`）：工具报错，但工单**真的建成了**。原因是返回对象里带了值为 `undefined` 的可选字段，被宿主判成"非无损 JSON"整包丢弃，而落盘时这些字段本来就会被丢掉，于是出现"报错但单据存在"的割裂。

当前源码已修（返回前统一清洗 undefined 键）。如果你还看到这个提示，说明跑的是旧代码，重启 DSH。

## 九、名词小抄

| 名词 | 人话 |
| --- | --- |
| **部门** | 一组员工的归属，有编号（`D01`）、职责关键词、产能上限 |
| **员工** | 一个可被派活的 AI 成员，有工号（`E0001`）、岗位、等级、模型 |
| **工号 / 部门号** | 自动编号，规则可改（默认 `E{seq:4}` / `D{seq:2}`） |
| **M / P 通道** | 两条职级线。M 是管理线（M1 主管 → M5 副总裁），P 是专业线（P1 初级工程师 → P6 首席专家），可以一人双线并存 |
| **工单（order）** | 你下的一件活，有类型、标题、验收标准、状态 |
| **派工记录（attempt）** | 这单派出去**一次**就记一条。同一单可以派很多次，历史全留 |
| **泳道** | 工作网上那五列，按状态给单子分栏 |
| **调度器** | 后台每 5 秒扫一轮，负责把单子往前推 |
| **产能** | 一个部门同时能跑几个任务 |
| **回报** | 员工干完（或失败）后写的结论，可能带产物路径和逐条验收结果 |
| **验收** | 你或经理对回报的最终裁决：通过 or 打回 |
| **临时工** | 只为几单存在的员工，可以设任务上限、会到期自动清扫 |
| **借调** | 把共享池里的人临时借到某个部门干活（自动派工**不会**替你借调，得手动点） |

## 十、边界与已知限制

先说清楚它不做什么，省得你踩坑：

- **改插件代码必须重启 DSH**，没有热重载
- **并发和预算是"看着"的，不是"拦着"的**——超了会显示，但不会真的阻止你派活
- **成本统计是进程内计数**，重启清零（历史账单看 `company/audit.jsonl`）
- **临时工没有独立人力成本**，钱只按 token 算
- **工具白名单（allow）在面板上改不了**，只能改代码或走 `company_admin`
- 旧包名 `dsh-plugin-member-manager` 的兼容层仍然保留，但**两个包不能同时启用**

## 十一、数据在哪

```
~/.dsh/storages/member-manager/
├─ registry.json            名册（显示名、岗位、技能、模型覆盖）
├─ company/
│  ├─ company.json          公司组织 + 工单账本
│  ├─ audit.jsonl           审计流水（谁在什么时候干了什么，只追加）
│  └─ ledger/               账本分片
├─ backups/                 名册备份（每次写入自动快照）
├─ boot.log                 启动日志
└─ workflow-stats.json      工作流采集数据
```

想整体搬走或清空，备份这个目录就行。**删掉 `company/` 等于公司解散**，名册还在。
