### 1.2 部门字段

`createDepartment(company, { id, name, code?, accepts?, capacity?, borrowPolicy?, charter? })`

- 新增 `code`（部门编号）：缺省时用 `nextDepartmentCode` 自动生成（默认 `D01`、`D02`…）。
- 显式传入时校验：去空格后非空、长度 ≤32、**不含空白字符**、全公司唯一（与其它部门 `code` 精确比较）。
- `updateDepartment` 的允许字段追加 `"code"`；改编号同样做唯一性校验。
- 新增只读派生字段（不写入存储）：`employeeCount` 由视图层计算。

### 1.3 员工字段

`createEmployee(company, { id, displayName, department?, role?, kind?, sessionPolicy?, state?, skills?, code?, channel?, level?, ... })`

- `code`（员工编号）：缺省自动生成（默认 `E0001`、`E0002`…；支持 `{dept}` 模板时取所属部门 `code`）。校验同上且全公司唯一。
- `channel`：`"M"` | `"P"`。缺省由 `role` 推导（manager→M，staff/window→P）。
  **一致性硬校验**：manager 只能是 M；staff/window 只能是 P；冲突抛 `OrgError`。
- `level`：必须是该通道等级目录中的 `code`（如 `M2` / `P4`）。缺省用 `DEFAULT_EMPLOYEE_LEVEL[role]`。
  显式 `level` 与通道不一致（前缀不符）抛 `OrgError`。
- `normalizeCompany` 迁移规则：历史员工缺 `channel/level/code` 时按上述默认补齐；`level` 非法时回退该 role 默认值并记 warning（**不丢弃员工**）。
- **Lead 裁决注记（实现后回填，2026-10-20）**：
  1. `normalizeCompany` 对「`channel` 非法或与 `role` 冲突」的历史数据同样按归正 + warning 处理（不丢员工），比本节字面更宽容，仅影响历史脏数据迁移路径。
  2. 因强制「`code` 以通道字母开头」，跨通道 `code` 重复天然不可能，实现不单独加跨通道重复校验。
  3. 无部门员工在含 `{dept}` 的编号模板下 `{dept}` 渲染为空串，模板退化为纯序号，符合 §3 语义。

### 1.4 晋升/转通道

```js
export function promoteEmployee(company, employeeId, patch = {}, { levels = DEFAULT_LEVELS } = {})
// -> { company, from: { channel, level }, to: { channel, level } }
```

规则（全部违反抛 `OrgError`）：

1. 无参：同通道**晋升一级**（等级目录顺序 +1）；已在最高级则报「已是最高等级」。
2. `{ level }` 同通道：目标下标必须是当前 **±1**（逐级晋升/降级），禁止跳级。
3. `{ channel }` 跨通道：必须同时显式给 `level`（目标通道任意合法等级），`role` 自动跟随通道（M→manager，P→staff）；转 M 时要求员工已有部门。
4. 不允许把 `window` 岗位转成 M 线（窗口不是管理岗）。

## 2. 配置（`src/shared/company-config.mjs`）

`resolveCompanyConfig(raw).org` 追加两个键（均支持 `org.*` 优先、根层回落；非法值回退默认 + warning）：

```js
levels: {
  M: { label: "管理通道", description?: "...", levels: [{ code: "M1", name: "主管" }, ...] }, // 至少 1 级
  P: { ... },
}
numbering: {
  employee: { pattern: "E{seq:4}", start: 1 },   // pattern 必须含 {seq}（或其带宽度形式）
  department: { pattern: "D{seq:2}", start: 1 },
}
```

- `levels` 校验：每个通道必须有 `label`（非空串）与 `levels`（数组 ≥1）；条目 `{code,name}` 均为非空串，通道内 `code` 唯一且以通道字母开头；跨通道 `code` 不重复。任一条非法 → 整个 `levels` 回退 `DEFAULT_LEVELS` + warning。
- `numbering` 校验：`pattern` 必须是非空字符串且包含 `{seq}`/`{seq:N}` 占位符；`start` 必须为正整数；允许占位符 `{seq}`、`{seq:N}`(1≤N≤8)、`{dept}`、`{channel}`、`{level}`；未知占位符 → 回退默认。
- 返回值增加 `config.levels`、`config.numbering`（已合并默认值）。

## 3. 编号规则（冻结）

| 占位符 | 含义 | 作用域 |
| --- | --- | --- |
| `{seq}` | 自增序号（十进制，无补齐） | 员工/部门 |
| `{seq:N}` | 自增序号零补齐 N 位（1≤N≤8） | 员工/部门 |
| `{dept}` | 员工所属部门的 `code`（无部门时为空串） | 仅员工 |
| `{channel}` | `M` / `P` | 仅员工 |
| `{level}` | 等级 code（如 `P4`） | 仅员工 |

- 生成算法：从 `start` 起递增，渲染模板，命中已用编号则跳号，最多尝试 100000 次，耗尽抛 `OrgError`（`code = "E_CODE_EXHAUSTED"`）。
- 显式编号优先于模板；显式编号必须全局唯一。
- `company.numbering`（持久化覆盖）> `resolveCompanyConfig().numbering` > `DEFAULT_NUMBERING`。运行时 boot 时解析一次，写回 `company.numbering` 以便面板/admin 展示。

## 4. 运行时接口（`src/host/`）

### 4.1 `view()` 形状（加法式扩展）

```js
view() -> {
  enabled, status, warnings,
  org: {
    departments: [{ id, name, code, accepts, capacity, charter, employeeCount,
                    managerId }],
    employees: [{ id, code, displayName, department, departmentCode,
                  channel, level, levelName, role, kind, state, sessionPolicy, skills }],
  },
  levels: { M: { label, description, levels:[{code,name}] }, P: {...} },
  numbering: { employee:{pattern,start}, department:{pattern,start} },

```

- `departmentCode` 取所属部门当前 `code`；无部门为 `null`。
- `levelName` 来自等级目录。
- `/company/overview` 返回体在既有 `enabled/status/org/board/costs/orders` 基础上追加 `levels`、`numbering`（`org` 内元素按上面形状）。
- `/company/org` 返回 `{ departments, employees }`（同上形状）。

### 4.2 工具（工具总数不变：13 个 company_*）

- `company_hire` 参数追加（全部可选）：
  `code`（string，员工编号，自定义）、`channel`（enum `["M","P"]`）、`level`（string，如 `"P4"`）。
  行为：编号冲突/等级非法 → `{ok:false, code:"E_INVALID_INPUT"|"E_DUPLICATE_CODE", message}`，不写盘。

  - `updateDepartment`：`args = { id, code?, name?, accepts?, capacity?, charter? }`

- 成功返回统一 `{ok:true, ...}`，涉及编号/等级的返回带上新值（如 `{ok:true, code:"P004", employeeId}`、`{ok:true, from:{...}, to:{...}}`）。

## 5. 可视化面板（`lib/client.js`）

- **v3 变更（2026-10-20 23:50，Lead 定稿）**：「部门架构」不再占页签，改为总架构页内按钮唤起的**弹层（次级页面）**，用于查看与修改成员。

### 5.1 总架构页（`CompanyOrgPanel` 扩展）

公司级只读全景（只用既有 `S` 样式 + 少量新增样式，不引入依赖）：

1. KPI 统计：部门数、员工数、M 线人数、P 线人数、工单数、已完成工单（`board {orders, done}`）、Token 合计、请求数（`costs {tokens, requests}`）。
2. 编号规则小字：`员工 E{seq:4} · 部门 D{seq:2}`。
3. 等级图例：M1…M5（琥珀）、P1…P6（蓝）chip，带等级中文名。
4. 部门卡片：`[D01] 部门名` + 编制 + M/P 分栏员工行（工号 / 等级徽章 / 姓名 / 岗位 / 状态点）；无员工空态；未分配部门卡（`cpNoDept`）。
5. **成本归因区**：Token 合计/请求数 + 三列（按员工 / 按部门 / 按工单），各取 tokens 降序 top5；员工列显示「姓名 · 工号」、部门列显示「编号 名称」、工单列显示 orderId，每项附 tokens/requests；无数据显示 `cpNoCost`。
6. 空态：公司未启用/未 boot → 提示「公司化运行时未启用」；启用但空组织 → 提示用 `company_admin` 建部门、`company_hire` 招人。

### 5.2 部门架构弹层（次级页面，原 `org` 页）

按 registry 小组（部门）组织成员管理，**只在用户主动打开时出现**：

1. **入口（总架构页内）**：① 工具栏「部门架构」按钮（`cpOpenDeptOrg`），打开弹层且默认「全部部门」；② 每张部门卡片头部「部门架构」按钮，打开弹层并预设该部门过滤。两处都不得改变当前页签（打开弹层时页签仍是 `company`）。
2. **弹层结构**：复用既有 `S.modal` 遮罩 + `S.modalPanel` 卡片（与「一句话建组」「技能选择」同款）：遮罩点击关闭、卡片内部点击不关闭、右上角关闭按钮（`cpClose`）、标题 `tabOrg` + 副标题提示；支持 ESC 关闭（`useEffect` 注册 keydown，卸载清理）。
3. **内容复用 `DeptOrgPanel`**：工具条（标题、刷新、部门过滤 pills「全部部门」+ 各小组名、搜索框按 姓名/DSH 名/岗位/技能 大小写不敏感过滤）、按小组分卡（名称/人数/说明/删除）、成员表过滤已停用成员、未分组卡「未分配部门」；成员行保留既有「编辑/停用/恢复/调整分组」操作（即查看与修改都在弹层内完成）。
4. 空态：筛选/搜索无匹配 → `cpNoMatch`；无任何成员 → 既有 `empty` 文案；被预设部门已消失 → 回落「全部部门」。
5. 新建部门表单文案：新建部门 / 部门名称 / 部门说明；保留「一句话建组」入口。
6. 新增文案键：`cpOpenDeptOrg`（部门架构 / Department org）、`cpClose`（关闭 / Close）、`dpModalHint`（查看与修改成员：按部门分组、过滤与搜索 / View and edit members, grouped by department）；zh/en 严格一一对应。
7. 状态：Panel 新增 `deptOrg` state（`null` = 关闭；`"__all__"` 或部门 id = 打开并预设），放在既有 hooks 末尾（`briefOpen` 之后），供测试 seed。

### 5.3 视图归一契约

`buildCompanyOrgView(overview)` 扩展为：在既有 `{enabled, status, warnings, levels, numbering, cards, counts}` 基础上新增
`costs: { tokens, requests, byEmployee: [{id, name, code, tokens, requests}], byDepartment: [{id, name, code, tokens, requests}], byOrder: [{orderId, tokens, requests}] }`（数组按 tokens 降序、各 ≤5）与 `board: {orders, done}`；所有字段缺失/类型异常时归一为空值/0，绝不抛异常。

## 7. 兼容与风险

- 旧 `company.json`：boot 时 `ensureCompanyCodes` 自动补号并 `saveCompany`（只在有变化时写盘），审计追加 `company.codes.backfilled` 可观测。
- 旧面板/工具调用不受影响：新参数全部可选；`company_admin` 旧 action 行为不变。
- 面板数据接口是只读的；公司化默认 enabled 的宿主才会有数据，其余显示未启用提示。
- 版本保持 `0.3.0`，CHANGELOG 在 0.3.0 下追加「等级与编号」特性段。
