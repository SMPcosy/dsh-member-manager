### 1.2 部门字段

`createDepartment(company, { id, name, code?, accepts?, capacity?, borrowPolicy?, charter? })`

- 新增 `code`（部门编号）：缺省时用 `nextDepartmentCode` 自动生成（默认 `D01`、`D02`…）。
- 显式传入时校验：去空格后非空、长度 ≤32、**不含空白字符**、全公司唯一（与其它部门 `code` 精确比较）。
- `updateDepartment` 的允许字段追加 `"code"`；改编号同样做唯一性校验。
- 新增只读派生字段（不写入存储）：`employeeCount` 由视图层计算。

### 1.3 员工字段

`createEmployee(company, { id, displayName, department?, role?, kind?, sessionPolicy?, state?, skills?, code?, channel?, level?, ... })`

- `code`（员工编号）：缺省自动生成（默认 `E0001`、`E0002`…；支持 `{dept}` 模板时取所属部门 `code`）。校验同上且全公司唯一。
- `channel`：`"M"` | `"P"`。缺省由 `role` 推导（manager→M，staff/window→P）。
  **一致性硬校验**：manager 只能是 M；staff/window 只能是 P；冲突抛 `OrgError`。
- `level`：必须是该通道等级目录中的 `code`（如 `M2` / `P4`）。缺省用 `DEFAULT_EMPLOYEE_LEVEL[role]`。
  显式 `level` 与通道不一致（前缀不符）抛 `OrgError`。
- `normalizeCompany` 迁移规则：历史员工缺 `channel/level/code` 时按上述默认补齐；`level` 非法时回退该 role 默认值并记 warning（**不丢弃员工**）。
- **Lead 裁决注记（实现后回填，2026-10-20）**：
  1. `normalizeCompany` 对「`channel` 非法或与 `role` 冲突」的历史数据同样按归正 + warning 处理（不丢员工），比本节字面更宽容，仅影响历史脏数据迁移路径。
  2. 因强制「`code` 以通道字母开头」，跨通道 `code` 重复天然不可能，实现不单独加跨通道重复校验。
  3. 无部门员工在含 `{dept}` 的编号模板下 `{dept}` 渲染为空串，模板退化为纯序号，符合 §3 语义。

### 1.4 晋升/转通道

```js
export function promoteEmployee(company, employeeId, patch = {}, { levels = DEFAULT_LEVELS } = {})
// -> { company, from: { channel, level }, to: { channel, level } }
```

规则（全部违反抛 `OrgError`）：

1. 无参：同通道**晋升一级**（等级目录顺序 +1）；已在最高级则报「已是最高等级」。
2. `{ level }` 同通道：目标下标必须是当前 **±1**（逐级晋升/降级），禁止跳级。
3. `{ channel }` 跨通道：必须同时显式给 `level`（目标通道任意合法等级），`role` 自动跟随通道（M→manager，P→staff）；转 M 时要求员工已有部门。
4. 不允许把 `window` 岗位转成 M 线（窗口不是管理岗）。

## 2. 配置（`src/shared/company-config.mjs`）

`resolveCompanyConfig(raw).org` 追加两个键（均支持 `org.*` 优先、根层回落；非法值回退默认 + warning）：

```js
levels: {
  M: { label: "管理通道", description?: "...", levels: [{ code: "M1", name: "主管" }, ...] }, // 至少 1 级
  P: { ... },
}
numbering: {
  employee: { pattern: "E{seq:4}", start: 1 },   // pattern 必须含 {seq}（或其带宽度形式）
  department: { pattern: "D{seq:2}", start: 1 },
}
```

- `levels` 校验：每个通道必须有 `label`（非空串）与 `levels`（数组 ≥1）；条目 `{code,name}` 均为非空串，通道内 `code` 唯一且以通道字母开头；跨通道 `code` 不重复。任一条非法 → 整个 `levels` 回退 `DEFAULT_LEVELS` + warning。
- `numbering` 校验：`pattern` 必须是非空字符串且包含 `{seq}`/`{seq:N}` 占位符；`start` 必须为正整数；允许占位符 `{seq}`、`{seq:N}`(1≤N≤8)、`{dept}`、`{channel}`、`{level}`；未知占位符 → 回退默认。
- 返回值增加 `config.levels`、`config.numbering`（已合并默认值）。

## 3. 编号规则（冻结）

| 占位符 | 含义 | 作用域 |
| --- | --- | --- |
| `{seq}` | 自增序号（十进制，无补齐） | 员工/部门 |
| `{seq:N}` | 自增序号零补齐 N 位（1≤N≤8） | 员工/部门 |
| `{dept}` | 员工所属部门的 `code`（无部门时为空串） | 仅员工 |
| `{channel}` | `M` / `P` | 仅员工 |
| `{level}` | 等级 code（如 `P4`） | 仅员工 |

- 生成算法：从 `start` 起递增，渲染模板，命中已用编号则跳号，最多尝试 100000 次，耗尽抛 `OrgError`（`code = "E_CODE_EXHAUSTED"`）。
- 显式编号优先于模板；显式编号必须全局唯一。
- `company.numbering`（持久化覆盖）> `resolveCompanyConfig().numbering` > `DEFAULT_NUMBERING`。运行时 boot 时解析一次，写回 `company.numbering` 以便面板/admin 展示。

### 4.4 面板写接口（v4 新增）：`POST /api/dsh-member-manager/company/op`

面板要能「新建部门 / 招聘员工 / 晋升 / 停用 / 调岗」，但既有 `/company/*` 全是只读。新增一条写路由，挂在 runtime `routes` 里（方法 `POST`，路径 `/company/op`）；**body 由 `lib/index.js` 的路由 wrapper 解析为对象后作为 handler 第三参传入**（`handler(req, url, body)`），runtime 自己不做流解析。

请求体：

```json
{ "action": "createDepartment", "args": { "...": "..." } }
```

响应沿用 wrapper 信封：HTTP 200 `{ ok: true, data: <result> }`；`result` 为下表成功返回或 `{ ok: false, code, message }`（业务失败也用 200，与工具返回一致）。`action` 缺失/未知 → `E_UNKNOWN_ACTION`；`args` 非法 → `E_INVALID_INPUT`；JSON 解析失败由 wrapper 返回 HTTP 400 `{ ok:false, code:"E_BAD_JSON" }`。

| action | args | 成功返回 | 说明 |
| --- | --- | --- | --- |
| `createDepartment` | `id?`, `name*`, `code?`, `charter?`, `capacity?`, `accepts?` | `{ok:true, departmentId, code}` | `id` 缺省由 runtime 生成 `dept-<base36 时间戳>`；`charter` 即面板「说明」 |
| `updateDepartment` | `departmentId*`, `name?`, `code?`, `charter?`, `capacity?`, `accepts?` | `{ok:true, departmentId, code}` | 与 `company_admin.updateDepartment` 同语义 |
| `createEmployee` | `id?`, `displayName*`, `department*`, `role?`, `kind?`, `code?`, `channel?`, `level?`, `skills?` | `{ok:true, employeeId, code, channel, level, levelName}` | `id` 缺省生成 `emp-<base36 时间戳>`；角色/通道/等级校验复用 `createEmployee` |
| `promoteEmployee` | `employeeId*`, `level?`, `channel?` | `{ok:true, from, to}` | 逐级 ±1、跨通道须显式 level |
| `fireEmployee` | `employeeId*` | `{ok:true, employeeId, state:"fired"}` | 置 `state=fired`，保留记录与工号；可重复调用（幂等） |
| `moveEmployee` | `employeeId*`, `department*` | `{ok:true, employeeId, department}` | 部门必须存在；`permanent/temp/manager` 目标部门非空，`shared` 可传 `""` 清空 |

- 全部写操作必须走 `store.withLock` + `store.load()` 刷新后写回（与工具一致，避免面板与 Agent 并发覆盖），成功后 `store.saveCompany` 并 `appendAudit`。
- 审计 `type`：`department_created` / `department_updated` / `employee_hired`（createEmployee）/ `employee_promoted` / `employee_fired` / `employee_moved`；均带对应 id。
- `company_admin` 工具的 6 个 action 枚举**保持不变**（不因面板写接口扩枚举）；op 与工具共用内部实现，但不改变工具契约。
- 路由总数：15 → **16**（新增 `POST /company/op`）。
- 安全边界：面板写接口仅本机 Web 面板使用（宿主绑 127.0.0.1），不经 Agent 工具线；工具线的三保险（restrict/guard/执行体反查）不受影响。

### 5.2 部门弹层（次级页面）

部门图框点击打开，**页签两个**，默认第一个：

1. **结构**：复用 `S.modal` 遮罩 + `S.modalPanel`（遮罩点击关闭、卡片内点击不关、右上角关闭按钮 `cpClose`、ESC 关闭并清理监听）；卡片头 = `[D01] 部门名` + `tabOrg`/`dpModalHint` 副标题 + 页签按钮「部门架构图 / 成员详情列表」（`cpModalChart` / `cpModalMembers`）+ 关闭。
2. **页签一：部门架构图**：顶部负责人卡（M 等级徽章 + 姓名 + 工号；无负责人显示 `cpNoLeader`）；下方 M / P 两栏员工列表（按等级从高到低，行同 §5.1 员工行样式，无编辑按钮）；无员工时 `cpDeptEmpty`。
3. **页签二：成员详情列表**（可读可改）：顶部工具条「招聘员工」（`cpHire`）+ 本部门人数；每行 = 工号 / 等级徽章 / 姓名 / 岗位 / 状态点 / 操作按钮：
   - `晋升`（`cpPromote`）：展开内联表单，选择目标等级（默认同通道下一级；通道下拉默认当前通道，改为跨通道时必须同时选等级），提交调用 `promoteEmployee`；
   - `停用`（`cpFire`）：`window.confirm` 确认后调用 `fireEmployee`；已停用行按钮禁用并显示状态；
   - `调岗`（`cpMove`）：展开内联表单选择目标部门（不含当前部门；`shared` 可含「不分配部门」），提交调用 `moveEmployee`；
   - `招聘员工`：展开内联表单：员工 ID（可选，留空自动生成）、姓名*、角色 `staff/manager/window`、等级（可选，留空按角色默认）、通道（可选，留空随角色）、类型 `permanent/temp/shared`，提交调用 `createEmployee`（所属部门 = 当前弹层部门）。
   - 所有写操作成功后刷新 overview（弹层保持打开），失败在弹层内红字显示 `{code}: {message}`。
4. 被删部门/失效 id → 弹层自动关闭。

### 5.3 新建部门对话框（合并「一句话建组」）

主界面工具栏「新建部门」打开；复用 `S.modal`：

1. 字段：`部门 ID`（可选，留空自动生成）、`部门名称`（必填）、`部门说明`（可选，写入 department.charter）、`编制人数`（数字，默认 4）、`一句话描述`（textarea，可选）+ `解析` 按钮 + 示例提示 `cpParseHint`。
2. 「解析」为纯客户端启发式（不发请求）：编制取 `编制\s*(\d+)` 或 `(\d+)\s*人`；部门名称取「新建/创建/成立/设立」之后到 `部|部门|组|，|。` 之前的文本（失败则取首个分句 ≤20 字）；部门说明在为空时填入原文。
3. `创建` 调用 `POST /company/op {action:"createDepartment", args:{id?,name,charter,capacity}}`；成功关闭对话框并刷新；失败显示 `{code}: {message}`。名称空/编制非法时按钮禁用。
4. 「一句话建组」不再有独立按钮/弹层。

### 5.4 视图归一契约

## 7. 兼容与风险

- 旧 `company.json`：boot 时 `ensureCompanyCodes` 自动补号并 `saveCompany`（只在有变化时写盘），审计追加 `company.codes.backfilled` 可观测。
- 旧面板/工具调用不受影响：新参数全部可选；`company_admin` 旧 action 行为不变。
- 面板数据接口：5 条只读 `GET /company/*` + 1 条写接口 `POST /company/op`（§4.4，仅面板使用，走同一套锁/校验/审计）；公司化默认 enabled 的宿主才会有数据，其余显示未启用提示。
- 版本保持 `0.3.0`，CHANGELOG 在 0.3.0 下追加「等级与编号」特性段。
