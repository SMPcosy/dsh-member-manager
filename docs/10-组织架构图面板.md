# 10 · 组织架构图面板（v0.2.3：右侧边栏 tab）

> 目标：把名册里的层级关系固化成一张常驻的「组织架构图」，放在 DSH **右侧边栏**里；
> 每个成员一块工作区，任务活动时按分发与依赖画动态引导线。

## 1. 载体：`sidebar.right` 的常驻 tab（v0.2.3 重做）

v0.2.1/v0.2.2 曾用 `document.body` 上的 `position: fixed` 覆盖层（可拖拽、可磁吸左右）。
用户明确要求「不要浮动窗口，放到右侧边栏」，因此 v0.2.3 把载体换成 DSH 壳自己的右栏：

| 步骤 | API | 说明 |
| --- | --- | --- |
| 声明 tab 类型 | `ctx.sidebarRightTabs.register({ id, kind, priority, title, keepMounted })` | 必须在 `ctx.effect(...)` 里注册；`id` 全注册唯一（`dsh-member-manager/orgmap`），`kind` 是 `openTab` 的页面身份（`member-orgmap`） |
| 注册 tab 正文 | `ctx.slots.inject("sidebar.right.pane.tab", () => ctx.slots.register({ name, key, locale, inject }, Body))` | keyed seat，`key` 必须等于定义 `id`；正文是普通 React 组件 |
| 打开右栏 | `ctx.sidebarRight.openTab(kind)` | 首次接线自动打开一次 |
| 重新打开入口 | `conversation.session.header.actions` 列表插槽 | 用户关掉 tab 后，会话头部有「组织架构」小按钮 |

实现要点：

- 右栏服务用**可选注入** `ctx.inject(["sidebarRightTabs","sidebarRight"], ...)`，服务缺失时静默降级，不阻塞插件其余部分；
- 图表主体 `createOrgChartOverlay({ embedded: true, host })` 内嵌到 tab 正文的宿主 `div`：`position: relative`、宽高 100%，无拖拽/磁吸/独立标题栏，折叠按钮保留；
- 结构线与动态线的画法不变（见 §3），动态线在窄面板里改走**左侧沟槽**的括号式折线，避免卡片占满整行时右缘没有留白；
- 卸载时 `overlay.destroy()` 清定时器、事件与节点。

## 2. 数据来源

浮层只读，不写任何状态；轮询 `GET /orgmap`（默认 2 s，可折叠/挂起）：

```
GET /api/dsh-member-manager/orgmap
{
  ok: true,
  data: {
    version: 1, generatedAt, enabled,
    lead: { target, displayName, title, model, provider, status, live, usage:{total,requests}, elapsedMs, work },
    groups: [{ id, name, order, members: [card...] }],
    ungrouped: [card...],
    members: [card...],
    dispatch:   [{ from, to, taskId, subject, status }],   // Lead → 成员
    dependency: [{ from, to, taskId, upstreamId, status }],// 成员 → 成员（task.blockedBy）
    totals: { totalTokens, requests, ... },
    taskCounts: { pending, in_progress, completed },
    tasksAvailable, tasksError, team
  }
}
```

宿主侧（`lib/index.js` 的 `orgmapSnapshot()`）把两个已有数据源拼起来：

1. `workflowSnapshot()` —— 成员状态、token、用时、当前工作包（旁路采集 `session/event` 的 usage，不阻塞会话）；
2. `service.view()` —— 分组与成员名册；
3. 任务板（`agentTeams.listTasks`）—— 分发边与依赖边；任务板不可用时 `tasksAvailable:false`，浮层降级为只画名册与用量。

卡片字段：`{ target, displayName, title, groupName, model, provider, status, live, usage:{total,requests}, elapsedMs, work }`。
Lead 从分组里剔除，避免同一人出现两次。

## 3. 视觉与交互

- **工作区卡片**：运行状态圆点、显示名、模型徽标、任务简介（截断 52 字）、`token / req / 用时 / 任务状态`；
- **引导线**：SVG 三次贝塞尔，走左侧留白导轨（每条线错开 4px 防止重叠），最多 12 条；
  - `dispatch`（Lead 分发）蓝色实线；
  - `dependency`（任务依赖）琥珀虚线；
  - `in_progress` 的边加 `mmo-edge-active`，`stroke-dashoffset` 动画产生流动效果；
  - `completed` 的边不画，避免糊成一团；
- **面板内布局**：宽度由右栏决定（内嵌模式单列铺满），卡片宽度自适应；不再有拖动、磁吸与独立标题栏；
- **折叠**：`－` / `＋`，折叠后只留标题行；折叠态写入 `localStorage["dsh-member-manager.orgchart.v1"]`；
- **刷新**：`↻` 立即重拉 `/orgmap`（不改变 2 s 轮询）；
- **无动画偏好**：`prefers-reduced-motion` 下关闭脉冲与流动动画。

## 4. 性能与安全

- 轮询 2 s、失败自动挂起（手动刷新可恢复），不在主线程做重计算；渲染在 `requestAnimationFrame` 内一次完成；
- 只读接口，无写入、无模型调用、无外发；
- 数据全部来自本机进程内存与任务板，token 用量为**旁路统计**，不是账单口径；
- 面板只渲染在 DSH 右栏内，不覆盖会话区、不拦截页面点击；`pointer-events` 只作用于卡片与标题栏。

## 5. 降级

| 场景 | 表现 |
| --- | --- |
| 任务板服务不可用 | 只画名册与用量，`tasksAvailable:false`，脚注显示任务 0/0 |
| `/orgmap` 请求失败 | 标题栏圆点转红，显示错误行，自动轮询挂起（点 ↻ 立即重试） |
| 名册为空 | 只有 Lead 卡或空 lane，不报错 |
| 窄窗口（<790px） | DSH 右栏自动切全屏模式，图表随右栏铺满；可折叠 |
| 宿主没有 `sidebarRightTabs` 服务 | 不注册 tab、不报错，其余面板功能照常 |

## 6. 独立演示

`demo/org-chart-overlay.html` 是零依赖单文件演示：左侧 mock 会话区 + 右侧 392px 右栏 tab「组织架构」，mock 6 名成员分 3 组，每 2 s token 增长、状态轮转。浏览器直接打开即可，不需要 DSH。

截图：`demo/org-chart-preview.png`。

## 7. 已知限制

1. **不是严格甘特/时序图**：只画「当前活跃」的分发与依赖边，历史任务不回溯；
2. **跨组依赖**：线会跨越 lane，长距离时靠导轨曲线，密集时可能视觉交叉（上限 12 条）；
3. **token 口径**：按会话事件累计 `usage`，包含缓存命中与推理 token，与账单可能有差异；
4. **多标签**：每个会话各自拥有右栏 tab 实例，折叠态偏好共享 `localStorage`；
5. **无键盘导航**：按钮可 Tab 聚焦，但卡片本身不可键盘操作；
6. **容器依赖**：依赖 tab 宿主容器的尺寸与 `getBoundingClientRect`；无右栏服务的宿主不渲染该面板（静默降级）。


## 8. v0.2.2：右侧边栏 + 树形层级

用户反馈后改版（原自由漂浮 + 分区列表 → 常驻右侧边栏 + 层级树）：

- **默认常驻右侧边栏**：`dock` 默认 `"right"`，仍可 ⇤/⇥ 切到左侧；拖动不再是自由漂浮，松手按落点吸附最近一侧。
- **层级树形结构**：`大总管` 卡片居顶；其下一条主脊线（trunk）依次挂出**分组色块**（插件组/知识库组/未分组，6 色调色板），色块下再用组色竖轨 + 横向短支线串起**组内成员**，整体是正交连接线，符合「组织架构图」的读法。
- **工作区卡片保留**：成员名、模型、任务简介、token、请求数、耗时、任务状态徽标不变。
- **动态引导线保留**：分发（蓝）与依赖（琥珀）沿右侧留白走贝塞尔曲线，`in_progress` 带流动虚线动画，最多 12 条，完成态不画。
- 测试：client-bundle 33/33、host-plugin 69/69、全量 225/225 不变（渲染层改动不改变数据契约）。
- 独立演示与预览：`demo/org-chart-overlay.html`、`demo/org-chart-preview.png`。


## 9. v0.2.3：从浮动层改为右侧边栏 tab

用户原话：「我的意思是不要浮动窗口了，放到右侧边栏」。因此彻底移除 `document.body` 覆盖层载体：

- **载体**：`sidebar.right` 的 keyed tab（正文挂载见 §1），默认跟随右栏开合/分屏/全屏；790px 以下窗口由右栏自动全屏。
- **不再有**：`position: fixed`、拖拽、磁吸左右、独立标题栏按钮（⇤/⇥）、位置偏好持久化；只保留折叠状态。
- **入口**：插件加载时自动 `openTab("member-orgmap")` 一次；关掉后可用会话头部「组织架构」按钮重新打开；`sidebarRightTabs` 缺失的宿主里不注册、不报错（降级为无此面板）。
- **内嵌渲染**：`createOrgChartOverlay` 新增 `embedded` / `host` 选项；内嵌模式挂进宿主 div、`data-embedded="1"`、忽略 `setDock`。
- **动态线**：窄面板里卡片占满整行宽度，右缘没有留白，故分发/依赖线改走左侧沟槽的括号式折线（`H lane V y H`），最多 12 条。
- **测试**：client-bundle 新增 3 条（tab 类型/正文/header 入口与自动打开、右栏服务缺失降级、内嵌模式挂宿主且忽略停靠）→ 36/36；全量 **228/228**。
- **演示**：`demo/org-chart-overlay.html` 重写为「模拟 DSH 壳 + 右侧栏 tab + 树形组织架构图」单文件演示（零依赖、2 s 跳动），预览 `demo/org-chart-preview.png`。
- **升级**：0.2.2 → 0.2.3 只改客户端载体，名册/数据目录/备份/更新状态全部兼容；仍需退出 DSH 后替换安装目录。


## 10. v0.2.4：去窗口框 + 并联/串联层级视图

用户原话：「不要额外的窗口框了，也不再需要位置按钮。组织架构的层级关系按照并联-横向，串联-纵向的视图方式呈现。」

- **无框**：面板内不再渲染标题栏、折叠、⇤/⇥、刷新按钮和外框；`root` 只有 canvas 与底部采样行为，直接铺满右栏 tab。唯一保留的交互是宿主右栏自身的开合/分屏/全屏与滚动。
- **并联—横向**：同一层级的兄弟卡片横向并排。第 1 层是大总管（单卡），第 2 层是各分组色块（横向并排），第 3 层是每组组内成员（横向并排）。整棵树 `width: max-content`，窄栏左右滚动。
- **串联—纵向**：父子之间只用纵向正交总线连接——大总管底部一条竖线落到总线，横向铺到各分组色块中心再竖向落下；每个分组色块底部再以组色竖线落到成员总线，横向铺到组内各卡片顶部。
- **视口居中**：首次绘制后把 `canvas.scrollLeft` 设到大总管中心（clamp 在可滚动范围内），避免大总管在左侧视口外。
- **动态引导线**：任务分发（蓝）与依赖（琥珀虚线）按“父上子下”走卡片外侧过渡带（`V → H 到目标 left-12 → V → H 到目标 cx → V`），不再压住分组色块或卡片；同层关系仍从卡片下方预留的 lane 绕行；`in_progress` 保留流动虚线，最多 12 条。
- **移除**：拖动、停靠/磁吸、`setDock`、折叠按钮、`orgmapDockSide`、`localStorage` 位置偏好。
- **数据契约**：`GET /orgmap` 不变（`groups[].members[]`、`edges`），版本号 `ORGMAP_VERSION = 2`。
- **测试**：client-bundle 36/36（断言无按钮、root 仅 3 个 DIV 子节点、以「V/H」正交路径绘制、组内两人横向并排）；全量 **228/228**。
- **演示**：`demo/org-chart-overlay.html` 重写为模拟 DSH 壳（左会话区 + 右栏 tab）+ 三层层级视图 + 2 s 跳动；预览 `demo/org-chart-preview.png`。

## 11. v0.3.0：只显示当前任务（按会话作用域）

用户原话：「我们重新来过。我要求只显示当前小组的可视化工作流。」，随后澄清：「按照会话来区分，就是把一个会话当做一个任务，当前任务需要谁工作，就把谁加进来。任务切换用下拉菜单实现」。

- **任务 = root 会话**：宿主用 `ctx.get("agents").list()` 拿存活 agent，用 `agent.session.header.parentSession` 判断归属——没有 `parentSession` 的会话是任务根，有的话归到该根的同一个任务里。参与者只取「任务根 + 其子会话中能在名册里找到的成员」，不再渲染全团队。
- **数据来源**：`GET /orgmap`（`version: 2`，支持 `?task=<rootSessionId>`）。返回 `tasks[]`（id/title/updatedAt/running/memberCount/members）、`task`、`lead`、`groups[].members[]`、`members[]`、`dispatch`、`dependency`、`totals`；标题来自 `ctx.get("sessionTitle")` 的快照，缺失时为空串。
- **切换**：右栏 tab 顶部一个任务下拉（数据来自 `tasks[]`，运行中的任务带 `●`、显示人数）。切换只改 `taskId` 并立即重取；没有任务时显示空态并禁用下拉。未知/失效的 `?task=` 由宿主回落到最近活跃任务。
- **用量口径**：卡片上的 token / 请求数取该任务各会话在 tracker 里的累计值（`tracker.sessions`），用时取该 agent 的累计活动时长（运行中再加当次增量）；不再把整个名册的用量加总。
- **布局**：沿用 v0.2.4 的并联横向 / 串联纵向三层视图；只有一个分组时整簇居中，窄栏仍横向滚动。
- **降级**：任务板缺失时 `tasksAvailable: false` 原样透出（依赖线为空）；工作流观测关闭时 `enabled: false`、参与者仍按会话关系列出但用量为 0。
- **测试**：host-plugin 替换为任务作用域用例（version 2、单任务两参与者、`?task=` 回退）→ 69/69；client-bundle 新增任务下拉 / 切换 / 空态三条 → 38/38；全量 **230/230**。
- **演示**：`demo/org-chart-overlay.html` 重写为「模拟 DSH 壳 + 右栏任务下拉 + 当前任务层级图」，内置两个任务可切换；预览 `demo/org-chart-preview.png`。
