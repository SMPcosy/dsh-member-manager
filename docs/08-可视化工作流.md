# 08 · 可视化工作流面板（0.2.0）

> 目标：让「谁在干什么、花了多少 token、用了多久」变成一眼可见的事实，而不是靠对话里翻记录。
> 设计红线：**旁路采集，绝不阻塞会话**；数据只在本机；任务板不可用时明确降级。

---

## 1. 面板长什么样

Web 面板新增「工作流」页签（`tab === "workflow"`），包含三块：

1. **KPI 胶囊**：活跃成员数 / 累计 token / 请求数 / 缓存命中率 / 累计用时 / 任务数。
2. **成员表**（8 列）：状态点 + 成员（显示名/`target`）、岗位、当前工作包（任务标题 + 状态 + 用时）、模型、token（入/出）、请求数、累计用时。
3. **任务板**：按 pending / in_progress / completed 分组，显示负责人与用时。

底部标注「采样于 HH:MM:SS」和自动刷新开关（默认每 2 秒轮询 `GET /api/dsh-member-manager/workflow`）。

## 2. 数据从哪来

| 面板字段 | 数据源 | 采集方式 |
| --- | --- | --- |
| token 入/出、请求数、缓存读 | 宿主 `session/event` 的 `assistant/message.data.usage` | 事件回调里只做内存累加；定时（默认 5s）落盘 `workflow-stats.json` |
| 成员状态（running/idle/unknown） | `agent/created`、`agent/status` 生命周期 | 复用宿主已经发出的 `{agent}` 载荷，不额外订阅 |
| 累计用时（activeMs） | 状态区间累加 | running 开始记 `runningSince`，转 idle 时结算 |
| 当前工作包、任务状态 | 官方 agent-team 的任务板（只读） | 每 3s 用 Lead agent 的身份调 `agentTeams.listTasks`，取 `projectTaskView` 的投影 |
| 工作包用时 | 观测器第一次看到该任务的时间 | 任务板**没有时间字段**，所以只能由本插件观测推算：从首次看到开始计时，completed 后冻结 |
| 模型 / 岗位 / 分组 | 本插件的名册 | 直接读 `registry.json` 视图 |

实现文件：`src/host/workflow.mjs`（`WorkflowTracker`），宿主接线在 `lib/index.js` 的「工作流观测器」段，路由 `GET /workflow`，工具 `member_workflow`。

## 3. 为什么不阻塞会话

- 会话事件回调只做 map 累加，O(1)，不读盘、不发请求；
- 落盘在独立定时器里做（原子写：tmp + rename），且 `unref()` 不阻止进程退出；
- 任务板轮询失败只记 `tasksError`，不抛错、不清空已有任务；
- 观测代码整体包 try/catch，最坏情况是面板少一块数据，绝不会让会话失败。

## 4. 隐私与边界

- 只采集 **token 计数、状态、任务标题/描述投影、成员名**，不采集消息正文、不采集工具参数。
- 数据写在本机 `{dataDir}/workflow-stats.json`，默认 `~/.dsh/storages/member-manager/workflow-stats.json`；没有任何外发请求。
- 超出 retention（默认 6 小时）的已结束会话在快照与加载时被剔除；内存里最多保留 400 个会话。
- 面板只是 Web GUI 的一个页签，不新开端口；所有请求走本插件已有的回环 HTTP 路由。

## 5. 降级行为

| 情况 | 表现 |
| --- | --- |
| 没装官方 agent-team / 当前 agent 不是团队成员 | `tasksAvailable:false` + `tasksError`，成员表照常显示，工作包列为空 |
| `workflow.enabled=false` | 不创建观测器；`member_workflow` 返回 `enabled:false` 的说明 |
| 状态文件损坏 | `load()` 返回 `LOAD_FAILED`，从空状态开始；不影响名册 |
| 进程重启 | 从 `workflow-stats.json` 恢复未过期会话；运行中的 agent 重新登记（runningSince 重置，不虚增用时） |

## 6. 配置

```jsonc
{
  "workflow": {
    "enabled": true,        // 关闭可视化工作流采集
    "persistMs": 5000,      // 落盘间隔（>=1000）
    "retentionHours": 6,    // 已结束会话保留时长
    "tasksPollMs": 3000     // 任务板轮询间隔（>=1000）
  }
}
```

## 7. 已知限制

1. **任务板没有时间戳**：工作包「用时」是观测时间，不是真实开工时间；插件重启后从重启时刻重新起算。
2. **token 归属**：一个成员可能有多个会话，面板按成员聚合（同名 target 合并）；未登记名册但观测到用量的 target 也会单列一行，避免账对不上。
3. **缓存命中率**：`cacheRead / (input + cacheRead)`，不同 provider 的 usage 字段语义略有差异，属于估算口径。
4. **只观测不干预**：面板不提供「取消/暂停成员」按钮，避免把可观测性做成新的控制面。

## 8. 独立演示

`demo/workflow-panel.html` 是一个**不依赖 DSH、不依赖构建**的静态演示页：内置 mock 快照，每 2 秒让 token 与用时增长、状态轮转，用来直观展示面板形态与交互。直接用浏览器打开即可。

> 演示页只用于「看形态」，真实数据以 Web 面板「工作流」页签为准。
