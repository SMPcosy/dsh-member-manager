# dsh-member-manager · 需求与设计决策

> 状态：需求已定稿，API 细节待三项研究结论回填（见文末「待确认」）。
> 创建：2026-10-15

## 1. 目标

为 DSH 开发一个「成员管理」插件，覆盖用户提出的 5 项能力：

| # | 用户诉求 | 本插件的对应功能 |
|---|----------|------------------|
| 1 | 团队的组织架构 | 两级结构：**小组 → 成员**，可创建/重命名/排序小组，成员归组 |
| 2 | 成员删除和添加 | 添加＝登记已有 target 或触发新建成员；删除＝**软删除**（保留历史，可恢复） |
| 3 | 成员重命名 | 设置**中文显示名**（displayName）与别名 |
| 4 | 岗位职责 | 岗位名称（title）＋ 职责条目列表（duties） |
| 5 | 技能赋予 | 给成员挂技能标签，并与 DSH 原生 skill 关联 |

形态：**宿主端工具（Agent 可调用）＋ Web GUI 管理面板（人可点选）**。

## 2. 硬约束（实测确认，决定了整体架构）

1. **成员名（target）强制 lower-kebab-case**。实测尝试用「数据整理员」作为成员名，工具直接返回：
   `Error: teammate name must be lower-kebab-case, at most 64 characters, and not "lead"`
2. **DSH 核心没有「重命名成员」工具**，也没有「删除成员」工具 —— 现有团队工具有：
   `spawn_teammate` / `list_agents` / `send_message` / `interrupt_agent` / `wait_agent` / `team_task_*`。
3. 因此**不能**通过核心实现「中文名」与「删除」。这是本插件存在的根本理由。

## 3. 架构决策（已与用户确认）

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 插件形态 | **工具 + Web UI 面板** | 让 Agent 与人都能管理成员 |
| 改名/删除实现 | **插件自建名册层**（overlay registry） | 核心 target 不动；插件维护中文名/别名、分组、岗位、技能、软删除标记。无 DSH 升级覆盖风险，不碰 `app.asar` 内的官方包 |
| 组织架构深度 | **两级：小组 + 成员** | 足以表达「产线组 / 质检组」类真实班组，复杂度可控 |
| 项目位置 | `C:\Users\Ren\Documents\deepseek-harness\default-workspace\dsh-member-manager` | 与既有 `dsh_plugin_rank` 同级，不污染知识库目录 |
| 包名 | `dsh-member-manager` | 可改 |

### 3.1 关键设计：名册层是「覆盖层」，不是「替代层」

```
DSH 核心团队状态（真相来源：target 列表、状态、父子关系）
        │  只读同步
        ▼
插件名册层 registry.json  ← 本插件拥有
   displayName / groupId / title / duties / skills / status
        │
        ├─► 宿主端 tools：Agent 读写名册
        └─► Web 面板：人以组织架构视图读写名册
```

**原则**：
- 核心的 `target` 是**唯一键且只读**。显示名、分组、岗位、技能全部存在插件自己的 registry 里。
- 名册里出现但核心已不存在的 target → 标记为「孤儿」，UI 提示，不自动删除。
- 核心存在但名册里没有的 target → UI 提示「未登记」，一键登记。

## 4. 数据模型（草案）

```jsonc
{
  "version": 1,
  "updatedAt": "2026-10-15T05:40:00+08:00",
  "groups": [
    { "id": "g-1", "name": "数据组", "order": 1, "description": "知识库与数据核查", "createdAt": "..." }
  ],
  "members": [
    {
      "target": "data-organizer",        // 唯一键，来自 DSH 核心，只读
      "displayName": "数据整理员",         // 「重命名」改这里
      "aliases": ["整理员"],
      "groupId": "g-1",
      "title": "知识库整理员",             // 岗位职责：岗位名称
      "duties": ["清点与结构诊断", "整理建议产出", "源 md 改动执行"],
      "skills": ["file-processing-master", "office-docx"],
      "status": "active",                 // active | retired
      "retiredAt": null,
      "note": "",
      "createdAt": "...",
      "updatedAt": "..."
    }
  ]
}
```

- `status: "retired"` 即用户说的「删除成员」：从组织架构默认视图中移除，可在「已停用」分页查看与恢复。**不触碰 DSH 核心**（核心本来也删不掉）。
- `skills` 有两种取值来源：DSH 原生 skill（`~/.dsh/skills` 下的目录名，可校验）与自定义标签（仅作标注）。

## 5. 功能清单

### 宿主端 tools（草案，最终命名待 API 研究后定）

| tool | 作用 |
|------|------|
| `member_list` | 输出组织架构树（小组 → 成员），含显示名/岗位/技能/状态 |
| `member_add` | 登记一个 target 到名册（可同时设显示名、分组、岗位） |
| `member_remove` | 软删除成员（记 retired），可 `--restore` 恢复 |
| `member_rename` | 改 displayName / aliases |
| `member_set_role` | 设 title 与 duties |
| `member_set_skills` | 赋/撤技能 |
| `group_create` / `group_rename` / `group_assign` | 小组管理 |

### Web 面板

- 组织架构视图：小组卡片 → 成员行（显示名 + target + 岗位 + 技能徽章 + 状态）
- 行内操作：重命名、改组、设岗位、赋技能、停用/恢复
- 「未登记成员」提示区 + 一键登记
- 中文界面（`locale/zh.json`）

## 6. 非目标（明确不做）

- 不修改 `app.asar` 内的官方包，不 patch 官方团队内核。
- 不实现成员名（target）本身的改名 —— 核心不允许。
- 不做任意层级组织树（本次只做两级）。
- 不做权限/审批流。
