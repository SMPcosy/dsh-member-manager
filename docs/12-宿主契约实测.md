## 1 所有权与生命周期（lead 已定架构的落点）

| 事实 | 证据 |
| --- | --- |

**已定所有权模型（Builder 必须实现）**：
- 公司 owner = 一个**根级 runtime agent**：`ctx.agents.create({ sessionId, agentOptions })`（不传 parentAgent），重启后 `ctx.agents.resume({ resumeSessionId })`。`ownerSessionId` 持久化进 company.json。
- 所有员工（含 resident 经理）都是 owner 的**直接子级**：启动员工时把 `ownerHandle.agent` 传给子级创建的真实 parent（§4）。
- 部门 = 账本里的逻辑映射，不是会话挂载点、不产生运行时对象。
- shutdown：逐个 `cancel(cause, { keepInbox: true })` → `Promise.race([agent.whenIdle(), timeout])`（I3，whenIdle 可能永不 resolve）→ `handle.dispose()` → 最后 `ctx.subagents.drainChildren(ownerHandle.agent, remainingIds)` 兜底 → dispose owner。**不做层级递归**（B2：drainChildren 只认 direct child，证据见 §4）。
- 若 create/resume 不可用：boot 返回 warnings、工具返回 `E_NO_AGENTS`，不抛。

## 5 工具面（B1：白名单 + guard 双防线，全局注册是前提）

### 5.1 register（dsh-tools/lib/index.js:2969-2983）

- 注册面：全局（runtime 级 tools 服务）或某个 `agent.ctx`（scoped）。**scoped 会 shadow 全局同名**。
- 定义要求：`output = { schema, render, presentationMeta? }` 必填，否则 TypeError；`timeoutMs` 必须正数。
- 保留名：`name === "run_code"` 一律抛错，任何层面均不可注册。
- 每层重复注册同名抛错；成功返回精确 disposer。

### 5.2 restrict（dsh-tools/lib/index.js:2985-3005）

- 只接受**作用域上下文**（`agent.ctx`）。全局调用直接抛：
  `Error("tools.restrict() requires a scoped context (agent.ctx): a context-global restriction would mask every agent — deny the tool for the intended agent instead")`。
- filter：`{ allow?: string[]; deny?: string[] }`；两者都不给 ⇒ no-op 错；编译成 `{ allow?: Set, deny?: Set }`。
- 不能命名 `run_code`；**命名未知全局工具 ⇒ 抛错**（严格匹配全局名）。
- 成功 ⇒ 追加一个作用域限制层，返回精确 disposer。

### 5.3 限制的作用面 —— B1 的一手证据（dsh-tools/lib/index.js:3040-3041 原文）

```
"A restriction filters what a scope inherits — the global layer and every
 ancestor layer on its chain — and never what its OWN layer registers."
```

另见 :3047-3051 的历史批注：presets 把工具移到 agent 平面之后，（祖先贡献改变）child 的 filter 曾**静默失效**（不再报错也不再拦截）。

⇒ **员工子 Agent 的 setup 里「先 define 自己的工具再 deny」不成立**。正确做法（lead 已定）：
1. 13 个 `company_*` 工具**只在全局**注册一次（runtime.tools 或插件服务面），员工自身永远不注册。
2. 子 Agent 的 `setup(agentCtx)` 内第一件事：`agentCtx.tools.restrict({ allow: [...该线工具白名单...] })`。
3. 再注册 `tools.guard(exec => …)` 做第二道防线（见下），因「无 guard 能强制放行」——restrict 是过滤层，不是权威检查。
4. **白名单名字必须与全局注册名完全一致**（restrict 对未知名直接抛），所以 13 个工具名现在就要冻结，改名 = 全线炸。

### 5.4 guard（dsh-tools/lib/index.js:3008-3032）

- 注册面：全局或 `agent.ctx`。执行顺序：挂在 `tools/pre-execute` waterfall 之后。
- check 为同步函数：**返回字符串 = 拒绝并作为理由**；返回 void/undefined 放行。
- `guardReason(exec)` 检查顺序：global 层 → `chainLayers(exec.agent)` 由远及近（child→parent）；`exec.agent` 可反查发起 agent 身份 ⇒ 用它实现「exec.agent → 所属线」越权拒答。

## 7 停机顺序（V9 依据；lead 已定，此处只列证据链）

1. 逐个员工：`agent.cancel('parent' | { kind:'hook', reason:'company-shutdown' }, { keepInbox: true })`——证据 AgentCancelCause 合法值（dsh-subagent/lib/typert.host.js:301）、cancel 语义（dsh-agent-loop/lib/index.js:815-821）。
2. `Promise.race([agent.whenIdle(), timeout])`——whenIdle 无超时、可能永不 resolve（dsh-agent-loop/lib/index.js:870-875，I3）。
3. `handle.dispose()`——AgentHandle 唯一具备拆解权（dsh-agent/README.zh.md:117），dispose = 停循环/注销/移除会话/解作用域（README.zh.md:39）。
4. `ctx.subagents.drainChildren(ownerHandle.agent, remainingIds)` 兜底——只对 direct child 有效（dsh-subagent/lib/typert.host.js:236），所以兜底仅覆盖残留直接子级。
5. 最后 dispose owner handle。不做层级递归（B2）。
