# 27 · v0.4 工作网看板与派工闭环

> 版本：0.4.0 · 2026-10-25
> 对照参考：`dsh-agent-teams`（https://github.com/NanmiCoder/dsh-agent-teams）的调度器 / attempt 语义 / 临时工 / 成员属性

## 1. 解决了什么

用户对 v0.3 的两条意见，逐条对应：

| 意见 | 根因 | v0.4 处理 |
| --- | --- | --- |
| 工作网不该自动弹出 | `lib/client.js` `wireOrgChart()` 末尾调 `scheduleOrgMapAutoOpen(0)`，失败还每 2s 重试 5 次 | 删掉 `orgmapAutoOpened` 与 `scheduleOrgMapAutoOpen`，只保留 header 按钮的显式 `openOrgMapTab()` |
| 工作网「实际不可用」，下任务分不下去 | 见 §2 的六条链式缺陷 | 五级路由回退 + 真调度器 + attempt 生命周期 + 冷恢复 + 看板可视化 |

## 2. 派不出去的六条根因（v0.3）

1. **路由只有规则表**：`routeTypeToDept(order.type, routingRules)` 命中不了就返回 `null`，真实环境 `routingRules` 为空 → `E_NO_DEPT`；部门自己的 `accepts` 完全没被使用。
2. **失败即粘死**：`routeAndAssign` 先把订单 `queued→routed`，失败后没有出口回 `queued`；而调度器只扫 `queued` → 订单永久失踪。
3. **调度器是空壳**：只 `filter(state==="queued")`，没有依赖门禁、没有产能上限、没有优先级、没有搁浅恢复。
4. **attempt 只在内存**：`activeAttempts = new Map()`，宿主重启后所有回报被判 `E_STALE_ATTEMPT`，订单永久 `running`。
5. **唤醒可能静默失败**：`wakeAgent` 里 `agent = agents.get(sessionId)` 没 `await`，宿主返回 Promise 时恒真，`followup()` 静默不执行——成员根本没被叫醒。
6. **成员属性被账本重写吃掉**：`normalizeCompany` 按固定字段重建员工对象，v0.4 新属性（临时工计次、工具黑名单…）在第一次 `withLedger → store.load()` 后全部消失。

## 3. v0.4 的派工闭环

```
placeOrder → [queued] → routeOrder → [routed] → assignAndWake → [running] → report → review → [done]
                 ↑                        ↘ 路由/产能/无人失败：记 routeError + requeueIfRouted
                 └──────────── 调度器每轮（默认 5s）+ 下单事件 kick(0)
```

- **五级路由回退**（`resolveDepartment`）：`explicit`（订单指定部门）→ `rule`（规则表）→ `accepts`（部门接单范围，中文 1 字 / 英文 ≥3 字符 loose 匹配）→ `skills`（部门成员技能命中）→ `fallback`（有空闲产能的部门里最大者）。全落空返回 `{deptId:null, reason}`，面板直接显示原因。
- **依赖门禁**：派工前 `isOrderReady` 显式判定，未满足返回 `{code:"E_DEPS", blockedBy}`，不再靠 `transitionOrder` 抛错把订单粘住。
- **产能门禁**：`dept.capacity` 与在跑 attempt 数比较，超限 `E_CAPACITY` + 10s 退避；**满编部门只跳过自己，不再 `break` 整个调度轮**（否则一个满编部门饿死全公司）。
- **改派先吊销**：同一订单重派时，旧活 attempt 全部 `markAttemptStale(...,"superseded")`，旧 worker 的回报被判 `E_STALE_ATTEMPT`，不会两个人改同一份产物。
- **派工单**：唤醒消息带标题 / 项目 / 说明 / 类型 / 优先级 / 工号 / `attemptId` / 依赖 / 验收标准 / 执行要求（`company_accept` → 执行 → `company_report` → `ask_help`/`escalate`）。
- **失败回滚**：唤醒失败 → `markAttemptStale(...,"wake_failed")` + `running→failed→queued` + 成员回 `idle` + 审计 `wake_failed`。
- **冷恢复**：`hydrate({recoverOrphans:true})` 在 boot 时把 running 订单的活 attempt 判 stale、订单回队列，**并把卡在 working 的成员放回 idle**（否则重启后永远选不到人）。
- **搁浅回收**：`recoverStranded()` 只处理「running 且无任何活 attempt」的订单，不误杀正在干活的成员。
- **回报语义**：跨重启可回报（锁内重读账本）；已吊销 → `E_STALE_ATTEMPT`（带 `staleReason`）；已回报 → `E_DUPLICATE_REPORT`。

## 4. 临时工机制

- `kind: "temp"`：必须挂部门；`tempHiredAt` / `tempMaxTasks` / `tempCompleted` / `tempExpiresAt` 落盘。
- 计次退场：`report` 成功后 `tempCompleted+1`，达到 `tempMaxTasks` 自动 `state="retired"` + 审计 `temp_released`。
- 到期清扫：调度器每轮 `sweepTemps()`，`tempExpiresAt` 过期且手上无活 attempt → `retired`。
- 借调：`company_borrow` 允许 `shared` 与 `temp`；**自动派工永不自动借调**（借调是显式动作）。

## 5. 成员属性（对齐 agent-teams）

| 属性 | 取值 | 作用 |
| --- | --- | --- |
| `reasoningEffort` | minimal / low / medium / high / xhigh | 传给员工会话的推理强度 |
| `memberProvider` | spawn / fork | 派生方式（fork 继承上下文） |
| `maxDepth` | 0–3 | `0` = 禁止子代理，写进员工身份提示 |
| `toolPolicy` | `{allow[], deny[]}` | `deny` 命中 → `E_TOOL_POLICY: <tool> 在该成员的工具黑名单中`（`*` 全禁） |
| `sessionPolicy` | resident / per_task | 会话复用策略 |
| `tempMaxTasks` | ≥0 | 临时工任务上限 |

这些字段全部进 `EMPLOYEE_PATCH_FIELDS` 与 `normalizeCompany` 的保留清单——**不做后者，属性会被每次账本操作抹掉**（v0.4 实测 bug）。

## 6. 工作网看板

位置：右侧栏「工作网」页签，`board` 是 `root.children[4]`（视觉上用 CSS `order` 提到拓扑图上方，不打乱既有 DOM 锚点）。

```
┌ 任务看板 ────────────────────────────────┐
│ 待派 1 | 已路由 0 | 执行中 1 | 已完成 1 | 异常 0 │  ● 5s  ↻ 刷新  雇临时工  + 新任务 │
├──────┬──────┬──────┬──────┬─────────────┤
│ 待派 │ 已路由│ 执行中│ 已完成│ 异常        │   ← 五泳道，卡片带状态左边框色
│ ┌──┐ │      │ ┌──┐ │ ┌──┐ │             │
│ │卡│ │      │ │卡│ │ │卡│ │             │   ← 点卡片开右侧详情抽屉
├──────┴──────┴──────┴──────┴─────────────┤
│ 调度器/产能/路由失败原因                  │
└─────────────────────────────────────────┘
```

- KPI 五格 + 调度器状态灯（`data-state=running|stopped`）+ 手动刷新 + 一键跑一轮调度 + 雇临时工 + 新建任务。
- 卡片点开抽屉：订单全文、attempt 历史（吊销的标 `superseded`）、依赖、验收标准、耗时、路由失败原因；操作按状态给「派工（可指定成员或自动）/ 验收通过 / 驳回 / 升级 / 取消」。
- 面板动作走 `POST /api/dsh-member-manager/company/op`：`placeOrder` / `routeOrder` / `assignOrder` / `borrowOrder` / `reviewOrder` / `cancelOrder` / `escalateOrder` / `hireTemp` / `releaseTemp` / `runScheduler`。
- 数据面：`/orgmap` 额外返回 `orders / pipeline / health / deptStats`；`/state` 的 worknet 同步透传。

## 8. 已知限制

- 插件代码在 DSH 启动时载入内存，**改了要重启 DSH 才生效**（客户端 bundle 同样随宿主加载）。
- `hrAttrsBlock` 只暴露推理强度 / 派生方式 / 深度 / 会话策略 / 工具黑名单；`toolPolicy.allow` 目前仅保留原值，未在面板编辑。
- 临时工没有独立的「人力成本」计费，成本仍只按 token 归因。
