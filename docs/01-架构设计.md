## 1. 为什么必须做「覆盖层」而不是改核心

对官方 `@deepseek-ai/dsh-experimental-agent-team`（0.2.0-rc.2）的源码分析结论：

| 能力 | 内核是否支持 | 证据 |
|------|--------------|------|
| 加成员 | ✅ 唯一入口 `ctx.agentTeams.spawnTeammate(caller, request)`，需**精确的 live Lead Agent 实例**作授权凭证 | `<REF>\dsh-experimental-agent-team\lib\types\index.js:103-105`；`roster.js:223,65` |
| 改名 | ❌ | 无任何 rename/setName；`README.zh.md:208` 明示「不支持…重命名」 |
| 删除 | ❌ | 类方法全集无 remove/delete；唯一拆除路径是 dispose 时内部 `stopTeammates()`，且不写终态、不释放名字（`roster.js:218-220`） |
| 显示名/别名 | ❌ 无字段 | 成员记录是 `.strict()` 的 7 字段 schema：`id/name/description/provider/context/phase/error`（`projection.js:46-54`） |
| 岗位/技能绑定 | ❌ 无字段、无 API | 全包 grep `skill` 零命中；`dsh-skill` 与团队无代码关联 |
| 按成员指定模型 | ❌ | `spawnTeammate` 请求里没有 model 字段（`roster.js:222-262`） |

**关键红线**：成员的身份字段被投影层强制不可变 ——
`projection.js:199-204` 在应用事件时抛 `changed immutable identity fields`；
而 `journal.js:24-25` 一旦投影 `failure` 就使**该 Team 的所有操作永久抛错**。
因此「手工 append 一条改名事件」不是后门，而是把团队状态打坏。
⇒ 本插件**绝不写核心团队状态**。

## 3. 冻结的接口

### 3.1 工具（8 个）

| 工具 | 作用 | 关键参数 |
|------|------|----------|
| `member_list` | 组织架构视图（小组 → 成员 + 未分组 + 未登记） | `includeRetired`, `group` |
| `member_add` | 登记成员 | `target`(必填), `displayName`, `groupId`, `title`, `duties`, `skills` |
| `member_rename` | 改中文显示名/别名 | `target`, `displayName`, `aliases` |
| `member_remove` | 停用 / `restore:true` 恢复 | `target`, `restore` |
| `member_set_role` | 岗位名称 + 职责条目 | `target`, `title`, `duties` |
| `member_set_skills` | 技能整体覆盖 **或** 增量 add/remove（互斥） | `target`, `skills`, `add`, `remove` |
| `group_manage` | 小组 create/rename/delete/assign | `action`(必填) + 各自字段 |
| `member_sync` | 把核心已有成员批量登记 | 无 |

工具定义用**普通对象**传给 `ctx.tools.register(...)`，不 import `defineTool`
（本机 `@deepseek-ai/*` 未安装到 profile，运行时内部提供；照抄 `<NM>\@michengai\dsh-skills-manager\lib\index.js:312`）。
注册用 `ctx.effect(() => ctx.tools.register(tool), label)` 以便卸载。
`parameters` 用原始 JSON Schema；返回值经 `output.schema` 校验，模型可见内容由 `output.render(args, value)` 的 content block 决定。

> **成员名的两个不同约束（易错点）**：
> - `isValidMemberName` —— **名册**能表示的名字。**允许 `lead`**，因为 DSH 的 Lead 就是真实团队成员（name 固定为 `"lead"`），组织架构与 `member_sync` 都必须能覆盖它。
> - `isSpawnableTarget` —— DSH `spawn_teammate` 能创建的名字，**排除 `lead`**。
>
> 早期版本把后者误当成前者，导致 `member_sync` 静默丢掉 Lead、组织架构缺负责人。两者已分离，并有测试锁定。

> **装载韧性契约**：插件中任何「可选部分」失败都只允许降级，不允许让加载失败 ——
> 宿主端 `safeInject` 包住 `webServer` 注入、每条路由注册各自 try/catch；
> 客户端 `mountSlot` 包住每个插槽的 `inject` 与 `register`，字典注册也独立 try/catch。
> 最坏情况是「只剩 8 个工具、没有 Web 面板」。每一项都有对应测试。

### 3.2 HTTP 路由（`ctx.inject(['webServer'], ...)`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/dsh-plugin-member-manager/state` | 组织架构视图 + `coreAvailable`/`lastRefresh`/`cacheError` |
| POST | `/api/dsh-plugin-member-manager/op` | `{op, args}` 统一写入口，12 个 op |
| GET | `/api/dsh-plugin-member-manager/skills` | 本机已安装技能目录（面板技能弹层用） |
| GET | `/api/dsh-plugin-member-manager/models` | 可用 provider/模型目录（面板模型下拉用） |
| GET | `/api/dsh-plugin-member-manager/overrides` | 模型覆盖可观测性（诊断用） |
| GET | `/api/dsh-plugin-member-manager/health` | 元信息 |

统一信封 `{ok:true,data}` / `{ok:false,code,message}`；错误返回 400。
路由契约照抄 `<NM>\dshmarket\src\routes.ts:98-104` 的 `WebServerService.register({kind,path,handler})`。

### 3.3 客户端挂载点

`ctx.slots.inject(name, () => ctx.slots.register(options, Component))`：

| slot | kind | options |
|------|------|---------|
| `settings.section` | list | `id: NS, order: 32, label, locale: NS` |
| `sidebar.panellist` | list | `id: NS, order: 32, label, locale: NS` |
| `main` | keyed | `key: NS, locale: NS` |

客户端为**手写 bundle**，固定壳：
`window.__ModuleLoader__.load({ id, factory: (require) => module.exports })`，
内部只 `require("react")`（基座模块表内）。

> **为什么不用 esbuild**：本机 profile、DSH 运行时、全局都没有 esbuild；
> 而客户端代码是单文件、无 JSX、无相对导入，手写壳依赖更少、更可复现。
> 若将来要引入 antd 等库，再补 `scripts/build-client.mjs`（做法见 `<NM>\@xmanrui\dsh-im\plugin-src\client\build.mjs:12-37`）。

## 4. 核心成员列表的来源（重要限制）

`ctx.agentTeams.listMembers(agent)` 需要**精确的 live Agent 实例**做授权凭证
（`roster.js:52-57,65`），而 HTTP 路由里没有 agent。
因此：

- **工具路径**：`execute(args, exec)` 里拿 `exec.agent` → `tryMembership` → 若是 Lead 则 `listMembers` 刷新缓存
- **事件路径**：`ctx.on('agent/created' | 'agent/status')` 尽力刷新
- **HTTP 路径**：只读缓存

缓存为空时 `coreAvailable=false`，UI 明确提示「在对话里跑一次 member_list / member_sync 同步」，
**绝不把「读不到核心」误判成「成员都是孤儿」**（已用测试锁定该行为）。

## 5. 与 DSH 团队状态的边界

| 边界 | 约定 |
|------|------|
| 读核心 | 只读：`tryMembership` / `listMembers` |
| 写核心 | **从不**。不加 `team/*` 事件、不调任何 mutator |
| 数据归属 | 名册 JSON 只属于本插件；核心 roster 只读 |
| 卸载 | 移除 profile 条目即可；名册文件留在 `~/.dsh/storages/member-manager/`，可手工删除 |
