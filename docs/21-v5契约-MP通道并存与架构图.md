## 1. 领域模型（src/shared/company-org.mjs）

### 1.1 员工通道数据

- 员工新增规范字段 `channels: [{ channel: "M" | "P", level: <该通道等级> }, ...]`：
  - 长度 ≥ 1；通道不得重复；每个 level 必须属于对应通道目录（DEFAULT_LEVELS 或 config.levels）。
  - 顺序固定：M 在前，P 在后（规范化时排序）。
- **兼容字段**：`employee.channel` = 主通道（含 M 则 `"M"`，否则 `"P"`）；`employee.level` = 主通道等级。二者由 `channels` **推导**并在所有写路径保持同步（normalizeCompany / createEmployee / promoteEmployee / setEmployeeChannels）。
- `role` 约束放宽：
  - `manager`：必须含 M 通道（可并存 P）→ 违规 `E_CHANNEL_CONFLICT`。
  - `staff`：可只有 P；可被标记为 M（M 单独或 M+P 并存）。
  - `window`：只允许 P（不得含 M）→ 违规 `E_CHANNEL_CONFLICT`。
  - `kind` 不影响规则。
- `createEmployee` 默认（未传 channels 时）：manager → `[{M,"M2"}]`；staff → `[{P,"P3"}]`；window → `[{P,"P1"}]`。若只传旧的 `channel`+`level`，等价为单通道；若同时传 `channels` 与 `channel/level`，以 `channels` 为准。

### 1.2 新增导出（shared，全部纯函数、无 IO）

| 导出 | 签名 | 说明 |
| --- | --- | --- |
| `normalizeChannels` | `(employeeLike, levels=DEFAULT_LEVELS) => { channels, warnings }` | 从 `channels`/旧 `channel`+`level`/role 推导规范通道列表；非法等级丢弃该通道并按 role 补默认；不得返回空列表；不抛 |
| `primaryChannelOf` | `(channels) => "M"｜"P"` | 含 M 即 M，否则 P |
| `resolveChannelLevel` | `(employee, channel, levels=DEFAULT_LEVELS) => {channel, code, name}｜null` | 该员工在该通道的等级；没有该通道返回 null |
| `describeEmployeeChannels` | `(employee, levels=DEFAULT_LEVELS) => [{channel, level, levelName, primary}]` | 供 view/提示词/面板使用，永不抛 |
| `setEmployeeChannels` | `(company, employeeId, channels, {levels}={}) => {company, from, to}` | 校验见 1.1；`E_INVALID_CHANNEL`/`E_INVALID_LEVEL`/`E_CHANNEL_CONFLICT`/`E_LAST_CHANNEL`/`E_NOT_FOUND`；写回后同步 legacy 字段 |

`promoteEmployee(company, id, patch, {levels})` 扩展：
- `patch.channel`（可选，默认主通道）：在该通道内逐级 ±1（沿用现有 ±1 规则）。
- `patch.addChannel = {channel, level}`：新增通道（不得重复；window 不得 M）。
- `patch.removeChannel = "M"|"P"`：移除通道；至少保留 1 个（`E_LAST_CHANNEL`）；manager 不可移除 M（`E_CHANNEL_CONFLICT`）；window 无 M 可移除。
- 其余旧行为（无参升一级、跨通道显式 level）保持不变。

### 1.3 normalizeCompany 迁移

- 老员工无 `channels`：按旧 `channel`+`level` 生成单通道（缺失则按 role 默认），不丢员工。
- `channels` 非法（空/重复/等级不合法/role 冲突）：按 role 默认归正 + warning；window 含 M 时去 M 并 warning。
- legacy `channel`/`level` 与 `channels` 不一致：以 `channels` 为准归位 legacy（warning），保留其它字段。
- 三个冻结测试（company-org/ledger/router）必须保持全绿（它们不断言 channel/level）。

## 3. 宿主运行时（src/host/company-runtime.mjs、company-employees.mjs）

### 3.1 view()

- `view().org.employees[]` 增加 `channels: [{channel, level, levelName, primary}]`；保留 `channel`/`level`（主通道）。
- 新增 `view().management = { channel:"M", employees:[{ id, code, displayName, departmentId, departmentCode, departmentName, level, levelName, role }] }`：
  - 取所有含 M 通道的员工，按「部门编号升序（无部门最后）→ 等级降序 → 工号升序」排序。
  - 该集合是**展示聚合**，不写入 `company.departments`/`company.employees` 的归属字段。

### 3.2 工具

- `company_hire` parameters 增加可选 `channels: [{channel, level}]`（与旧 `channel`/`level` 互斥优先）；非法返回 `{ok:false,code,message}` 不抛。
- `company_admin` action 增加：
  - `setChannels`：args `{employeeId, channels:[{channel,level}]}` → 调 `setEmployeeChannels`，返回 `{ok:true, employeeId, channels, channel, level}`；审计 `employee_channels_set`。
  - `promoteEmployee` 透传 `channel`/`addChannel`/`removeChannel`（审计沿用 `employee_promoted`）。
- 员工提示词身份行（company-employees.mjs `buildPromptFor`）：单通道 `工号：E0002 · 等级：P3（专业技术，P 通道） · 部门：插件部（D02）`；双通道 `工号：E0002 · 等级：M2（管理，M）、P3（专业技术，P） · 部门：插件部（D02）`（主通道在前）。

## 4. 面板（lib/client.js）

### 4.1 总架构图（EmployeeCenter 节点移除、管理层置顶）

- **移除**架构图中的「员工中心」紧凑节点与「查看全部」按钮（员工中心仍为独立页签，从页签进入）。
- 最高层新增**「管理层」虚拟节点**：
  - 数据：优先取 `overview.management`；缺失时客户端从 `overview.org.employees` 过滤含 M 通道自行聚合（兜底不抛）。
  - 内容：标题「管理层」（`cpManagement`）、M 通道人数 badge；点击打开**只读弹层**（复用 `S.modal`/`S.modalPanel`，`cpClose`/遮罩/ESC 关闭）；弹层内为 M 通道员工只读列表（工号 monospace + 等级徽章 + 姓名 + 部门编号+名称），标题「管理层（只读展示，不影响部门归属）」（`cpMgmtHint`），空态 `cpMgmtEmpty`。
  - 管理层节点向下用**竖直连接线**连到部门行（每个部门图框），即：管理层 → 各部门；部门图框仍保留领导节点（部门内 M 通道最高等级者，沿用 v4 规则）。
- 布局允许横向滚动；不引入依赖，不改既有 KPI/编号/图例/成本三列。

### 4.2 双通道展示与编辑

- 员工行：等级徽章渲染 `channels`（每个通道一个徽章，M 琥珀 / P 蓝，含 levelName）；主通道在前。
- 部门弹层「成员详情列表」：每行编辑表单增加通道编辑：
  - M 复选框 + M 等级下拉（M1–M5）、P 复选框 + P 等级下拉（P1–P6）；至少勾一个；`window` 行 M 复选框禁用；`manager` 行 M 复选框禁用（不可取消）。
  - 保存走 `POST /company/op {action:"setChannels", args:{employeeId, channels}}`；成功后刷新 overview 且弹层保持；失败红字 `{code}: {message}`。
- 晋升按钮沿用 `promoteEmployee`，新增「晋升通道」选择（M/P，默认主通道）。
- 新建部门对话框/招聘表单：`channels` 可选（不传按 role 默认）；招聘表单提供 M/P 复选框 + 等级下拉。
