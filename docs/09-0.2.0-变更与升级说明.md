# 09 · v0.2.0 变更与升级说明

> 发布日期：2026-10-19 · 基线：v0.1.2 · 目标：把「插件更新把组织架构弄丢」这类事故，变成流程上不可能发生。

## 1. 背景

2026-10-19 的插件更新事故（见工作区 `_工具\DSH问题报告\DSH-plugin-update-problems-report-2026-10-19.md`）暴露了三件事：

1. Windows 上 `link:` 安装留下 junction，pnpm 的 `rename(tmp → node_modules/<name>)` 直接 `ERR_PNPM_EPERM`；
2. host 插件运行中被 DSH 加载，**运行中替换插件目录本身就不安全**；
3. 更新失败没有回滚，名册只靠一份 `.bak`，误操作即丢组织架构。

v0.2.0 的四个新能力各自对应一条：

| 新能力 | 对应问题 |
| --- | --- |
| 名册自动备份 + 一键恢复 | 更新/误操作丢组织架构 |
| 分阶段自动更新（check → stage → 离线 apply → rollback） | 运行中替换、无 staging、无回滚 |
| 一句话建组 | 建组/批量登记要来回点很多次 |
| 可视化工作流面板 | 谁在干什么、花了多少 token、用了多久不可见 |

## 2. 新增模块

| 文件 | 行数量级 | 职责 |
| --- | --- | --- |
| `src/shared/backups.mjs` | 449 | 名册快照、索引、轮转（keep + dailyKeep）、恢复（恢复前自动 pre-restore 快照）、导出 |
| `src/shared/group-brief.mjs` | 481 | 一句话建组：中文/英文自然语言 → {group, members[]}，目标名 slug、撞名加序号 |
| `src/host/workflow.mjs` | 404 | 工作流观测器：session/event 的 usage 聚合、agent 状态、任务板投影、定时落盘 |
| `src/host/updater.mjs` | 1181 | 分阶段更新：版本比较、registry 检查、tar 解析、暂存、5 道闸门、备份/回滚 |

## 3. 宿主行为变化

- **工具 12 → 16**：新增 `member_backup`、`member_group_from_text`、`member_workflow`、`member_update`。
- **HTTP 路由 6 → 9**：新增 `GET /backups`、`GET /update`、`GET /workflow`。
- **配置新增** `backups` / `update` / `workflow` 三块（均有默认值，不配也能用）。
- **启动时**：若 `backups.enabled`，写一份 `boot` 快照；若 `update.checkOnBoot`，只 check（可加 `autoStage:true` 自动下载到 staging），**从不自动应用**。
- **写名册时**：防抖 1.5s 自动快照（reason=`auto`），只保留最近 N 份 + 每天一份。
- **重命名/删除/恢复**：全部走原来的纯函数 mutator，未改变名册 schema（仍是 version 1），**0.1.x 的名册可直接用**。

## 4. 客户端变化

面板新增：

- 「工作流」页签：KPI + 成员表 + 任务板 + 2s 自动刷新；
- 「维护」页签：检查/暂存更新、显示离线应用命令、回滚更新 + 备份列表/立即备份/恢复；
- 组织架构工具栏「一句话建组」：输入自然语言 → 预览 → 确认创建（内置示例）。

## 5. 升级步骤（link 安装，当前 desktop profile 即此形态）

```powershell
# 0. 先备份名册（可选，0.2.0 启动后也会自动备份）
Copy-Item "$env:USERPROFILE\.dsh\storages\member-manager\registry.json" `
          "$env:USERPROFILE\.dsh\storages\member-manager\registry.json.manual-$(Get-Date -Format yyyyMMdd-HHmmss)"

# 1. 退出 DSH（不要运行中替换）
# 2. 更新源码目录（git pull 或覆盖文件）
# 3. 启动 DSH
# 4. 打开 Web 面板 → 维护：确认版本 0.2.0、备份开关、更新状态
```

> junction 安装下「自动更新」会返回 `JUNCTION_INSTALL` 并提示手工步骤，这是**有意的保护**，不是 bug。

### 以后用 staged 更新时（npm 真实目录安装）

```powershell
# 1. 面板「维护 → 检查更新 → 暂存更新」（只下载，不替换）
# 2. 完全退出 DSH
# 3. 在终端执行面板给出的命令（或下面这条）
node "<安装目录>\scriptspply-pending.mjs" --data-dir "$env:USERPROFILE\.dsh\storages\member-manager" --install-dir "<安装目录>" --yes
# 4. 启动 DSH
```

## 6. 回滚

| 回滚什么 | 怎么做 |
| --- | --- |
| 名册 | 维护页 → 备份 → 恢复（恢复前自动备份当前状态）；或 `member_backup {action:"restore",file:"..."}` |
| 插件版本（staged apply 之后） | `member_update {action:"rollback"}`（仅当上次 apply 由本插件完成） |
| 插件版本（手工） | 退出 DSH → 覆盖回旧版本目录 → 启动 |
| 全部 | 旧版 tgz + 名册备份都在，最坏情况手动恢复 |

## 7. 已知限制

1. 任务板没有时间戳，工作包「用时」是观测推算值（见 `docs/08-可视化工作流.md`）。
2. 自动更新在 junction/link 安装下不生效（安全闸门），需要 `git pull` 或 npm 真实目录安装。
3. **不提供在线应用**：`allowOnlineApply` 默认 false，面板 apply 只返回命令，实际替换必须在 DSH 退出后由 `scripts/apply-pending.mjs` 完成。
4. `apply` 不做「删除新版没有的旧文件」，残留文件不影响加载，但目录可能不干净。
5. token 归属按成员聚合，跨 provider 的 usage 字段语义有差异，命中率为估算口径。
6. 0.2.0 仍需**重启 DSH** 才能被加载（插件代码不走 HMR）。

## 附：v0.2.3（组织架构图载体改为右侧边栏 tab）

- **背景**：v0.2.1/v0.2.2 用 `document.body` 上的 fixed 覆盖层；用户明确要求「不要浮动窗口了，放到右侧边栏」。
